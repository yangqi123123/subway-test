# 项目巡查汇总通知设计文档

## 背景

当前移动端「今日巡线」流程中，用户在点击「填写」并提交人工巡检表单后，会立即向系统通知推送一条「项目巡查」通知。产品要求改为：当用户点击「完成当日巡线」并确认提交后，才生成一条汇总通知；通知内包含当天所有已完成巡线的项目，项目名称可点击并查看对应完整巡线记录。

## 目标

1. 将「项目巡查」通知的生成时机从「填写提交」改为「完成当日巡线确认提交」。
2. 「项目巡查」类型通知在列表中展示为一条汇总通知，包含消息标题、状态、通知类型、发布时间、已完成的项目名称。
3. 已完成的项目名称使用蓝色字体，点击后打开该项目对应的完整巡线记录详情（复用现有人工巡检详情弹窗）。

## 关键设计决策

- **一条汇总通知 / 每天**：点击「完成当日巡线」后生成/更新一条当天的汇总通知；同一日期重复点击时覆盖旧通知。
- **持久化巡线记录**：人工巡检记录提交时写入 `localStorage`，确保刷新页面后仍能在「完成当日巡线」时汇总当天记录。
- **通知标题格式**：`YYYY-MM-DD 用户1、用户2 已完成以下项目的巡查`（用户名为各记录 `user` 字段去重后的结果）。
- **列表展示**：汇总通知卡片内列出所有项目名称，每个项目都是蓝色可点击链接；点击项目名称即打开该项目详情。

## 数据结构

### 持久化的人工巡检记录

使用 localStorage key：`whmetro-manual-rows`

每条记录与现有人工巡检行字段保持一致，至少包含：

- `id`
- `line` / `direction` / `section` / `station`
- `projectName` / `projectType`
- `patrolDate` / `updatedAt`
- `progress` / `remark`
- `user`
- `taskId`（来自今日巡线的任务 ID，用于关联）

### 汇总通知行

追加到 `whmetro-notify-extra`，结构如下：

```js
{
  id: "task-notify-daily-YYYY-MM-DD",
  title: "YYYY-MM-DD 张三、李四 已完成以下项目的巡查",
  type: "项目巡查",
  time: "YYYY-MM-DD HH:mm",
  read: "未读",
  source: "今日巡线",
  projects: [ /* 当天完成的所有巡检记录对象 */ ]
}
```

## 交互流程

1. 用户在「今日巡线」列表点击某任务的「填写」，或在「人工巡检记录」页面新增记录，进入人工巡检表单。
2. 表单提交后：
   - 记录写入 `whmetro-manual-rows`；
   - 若来自今日巡线，则标记该任务已完成（`whmetro-today-task-done`）；
   - **立即生成/更新当天汇总通知**，不再推送单条通知。
3. 用户在今日巡线列表点击「完成当日巡线」→「确定」时，同样会重新生成/更新当天汇总通知。
5. 用户进入「系统通知」列表，看到一条「项目巡查」汇总通知。
6. 列表卡片内展示所有已完成项目名称；点击项目名称打开该项目的完整巡线记录详情。

## 涉及文件

- `app/assets/js/manual-page-boot.js`：移除填写时生成通知的逻辑，改为持久化巡检记录。
- `app/assets/js/today-task-page-boot.js`：在「完成当日巡线」确认后生成汇总通知。
- `assets/js/wb-notify-mobile-page.js`：支持 `projects` 数组的渲染与详情打开。
- `app/mine/pages/notify.html` 与 `app/assets/css/mine-mobile.css`：调整项目巡查通知卡片样式（标题换行、项目名称蓝色可点击）。
